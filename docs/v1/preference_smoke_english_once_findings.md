# Preference Track：英文单次 Smoke 结果

> 状态：有效的工程 smoke，但不是最终排名。全部 benchmark 外部输入均为英文，三个系统使用同一批 case、同一个 DeepSeek reader、同一决策 prompt，且每个 case 的存储完全隔离。本轮每个系统只运行一次，不能据此声称统计显著性。

## 产品结论

这轮主要回答两个问题：

1. 三种 memory 方案能否把多个 Agent 写入的用户偏好，正确交给最后做决定的 Agent；
2. 当偏好发生更新，或历史中混有一次性要求时，系统能否返回足够且适用的 context，让同一个 reader 选对方案。

公平口径应排除 `PREF-D-MERGE-002`。该题把正确选项 B 设计成“60 页、需要三小时审阅”，而选项 C 提供最强的逐步推理但只给高层证据摘要。即使拿到完整原文的 `naive_markdown` 也选择 C，三个系统中有两个选择 C，说明标准答案 B 在产品判断上不唯一，而不是 memory 一定失败。题目将在下一轮重新设计，不能看完本轮结果后修改并继续复用本轮分数。

## 怎么测

每道题都执行相同链路：

```text
多个 Agent 依次写入英文用户原话
        ↓
memory 系统保存、整理或索引信息
        ↓
最后一个 Agent 用固定英文问题检索 context
        ↓
同一个 DeepSeek 只看 context、当前任务和 A/B/C 候选
        ↓
输出 choice 和简短理由
        ↓
choice 与冻结的 ground truth 比较
```

为了判断失败发生在哪一层，每题同时保存：原始写入、系统内部 snapshot（支持时）、系统原生写入结果（支持时）、最终检索 context、DeepSeek 原始输出、解析后的选择、耗时和错误。

核心指标是最终选择准确率。理由只用于诊断，不作为核心计分，避免把“表达不同但选择正确”误判为失败。综合题以 A/B 两个反事实版本组成一对，两个版本都答对才算 pair success，用来检查模型是否真的随偏好变化而改变选择。

本轮 12 题包含：

- 6 道单项诊断题：跨 Agent 合并 2 道、偏好更新 2 道、长期偏好与临时要求边界 2 道；
- 6 道综合题：酒店、分析呈现、团队软件各一组 A/B 反事实对，同时组合合并、更新、作用域和临时要求判断。

## 为什么全部改成英文

此前中文轮次不能公平比较：mem0 会把中文用户原话抽取成英文 memory，而原配置的 `multi-qa-MiniLM-L6-cos-v1` 主要面向英文语义检索，中文 query 检索英文 memory 混入了跨语言 embedding 能力差异。

本轮不是只替 mem0 翻译 query，而是把三个系统收到的写入、query、当前任务、候选和 reader prompt 全部统一为英文。因此仍然比较 memory 链路，只是不再额外考察跨语言检索。之前的中文成绩已标记为不可比较，不进入本轮结论。

## 为什么出现这个结果

### `naive_markdown`

它不做抽取和检索裁剪，直接把本题所有用户原话按顺序交给 DeepSeek。短历史下信息损失最少，因此排除争议题后 11/11。

这说明“保留完整原文”是当前短 context 场景的强基线，不代表它在几百条长期记忆下仍然最好。历史变长后，它可能遇到 context 膨胀、无关信息干扰和成本上升。

### `mem0`

隔离修复后，mem0 在 11 道有效题中全部答对：没有空 context，没有写入管线警告；更新题同时返回旧偏好和明确的新偏好，reader 能正确采用新偏好；边界题同时返回长期偏好与过去一次性要求，reader 能按当前任务过滤；综合题也能随反事实偏好变化改变选择。

它平均返回 284.5 个字符，比完整原文基线少约 13%，说明在本轮短历史上，mem0 的抽取总结没有造成可观察的决策损失。但样本太少、历史太短，暂时不能证明它在真实长期记忆中优于 naive。

### `AMH`

AMH 返回的 context 最短，但发生两类有效错误：

1. `PREF-D-UPDATE-002`：应采用“现在重视最新功能和快速迭代”的新偏好，AMH 只检索到旧的“成熟、可预测、长期支持”，因此选了旧偏好对应的 C。这是更新信息检索遗漏。
2. `PREF-C-ANALYSIS-001-B`：context 为空，DeepSeek 在没有记忆证据时按通用默认选择 A，而 ground truth 是证据完整的 C。这是检索失败。

这两个错误都能从保存的 context 直接定位，不能归因于 reader 不会理解偏好。AMH 的短 context 带来更少输入，但本轮代价是漏掉了决定性信息。

## 本轮发现的工程问题

第一次英文 mem0 运行曾出现跨 case 污染：虽然 Qdrant 向量库使用了每个 adapter 独立的临时目录，mem0 还会默认使用全局 `~/.mem0/history.db` 保存最近消息。同一个 benchmark user 的旧消息因此进入后续 case 的抽取过程。

当前 adapter 已将 `history_db_path` 与 Qdrant 一起放入每个 case 的独立临时目录，并关闭不影响能力测试的全局遥测写入；新增回归测试后共 32 项测试通过。受污染的旧 mem0 文件已明确标记 `comparison_valid: false`，本报告只使用隔离修复后的最终文件。

这个问题也说明：benchmark 的“每题新建 adapter”不等于底层所有状态天然隔离，后续接入任何 memory 系统都必须检查向量库、消息历史、缓存和遥测等所有持久化位置。

## 现在能说什么，不能说什么

可以说：在这 11 道有效英文 smoke case、一次运行、短历史条件下，`naive_markdown` 与 `mem0` 都完整通过；AMH 出现两次决定性检索遗漏。英文统一后，mem0 此前大量空 context 的现象消失，说明中文轮次主要测到了语言链路问题。

不能说：mem0 或 naive 已经被证明总体优于 AMH；也不能说 mem0 在长历史、更多噪声、更多并发 Agent 或多次运行下仍为 100%。12 题单次 smoke 只能验证链路、公平性和初步区分度。

## 下一步

1. 先重写并重新冻结 `PREF-D-MERGE-002`，确保正确选项在真实产品判断上唯一；旧轮结果不回填。
2. 将 pilot 扩到约 30 题，而不是立即扩到几百题：单项约 12 题（合并、更新、边界各 4），综合约 18 题（6 组反事实对）。
3. 增加长历史与无关记忆噪声。当前每题仅 2～3 条写入，偏向完整原文基线，尚未体现检索型系统的主要价值。
4. pilot 先跑一次做质量检查；case 冻结后再跑 3 次看稳定性，报告平均值、波动和错误类型，而不是只给一个总分。
